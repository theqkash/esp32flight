M5Stack Tab5: now covering all three panel generations

2026-08-17 · board: M5Stack Tab5 (ESP32-P4, 5″ 1280x720 MIPI-DSI) · base: 0.4.4

The Tab5 shipped with three different display generations: ILI9881C + GT911 (early units), ST7123 and - as it turns out - ST7121. The last two answer at the same I2C address and only a touch-firmware version register tells them apart; the ST7121 also wants its own vsync timings and a completely different init sequence. This build probes the panel at boot the way M5's own firmware does and picks the right path. ILI9881C and ST7123 are hardware-confirmed; ST7121 owners wanted - yours is the untested one, the boot log will greet you with board: M5Stack Tab5 (ST7121).

Strobe report, round 2 (2026-08-17): the A/B result (A strobing, B black) confirmed a genuine ST7121 panel. Test A has been rebuilt around the vendored ST7121 reference driver from M5's own firmware - byte-for-byte their init path this time, not our re-creation of it. Flash the updated A; B stays up only as the comparison point:

Test A: auto-detect (0.4.4-tab5) - first install: check Erase device
Test B: ST7123 path forced (0.4.4-tab5-b) - for 0x55 units that strobe on A

Command line instead? One-shot image: esp32flight-0.4.4-tab5-full.bin - esptool.py --chip esp32p4 --port PORT write_flash 0x0 esp32flight-0.4.4-tab5-full.bin (back up first: read_flash 0 0x1000000 stock-backup.bin).

When reporting, include:

  • Which build (A or B) shows a stable picture.
  • The board: and sitronix touch fw version: lines from the boot log, if you can reach a serial console - they name your panel generation outright.
  • Does touch track your finger?
  • Which panel your unit has, if you know (purchase date helps map generations).

BigTreeTech Panda Touch: the Bambu pendant becomes a flight radar

2026-08-15 · board: BTT Panda Touch (ESP32-S3 R8, 5″ 800x480, GT911, battery) · base: 0.4.4

BTT's Bambu-printer remote is a regular ESP32-S3 smart display underneath, and BTT themselves publish the full pin map in their open PandaTouch_IDF SDK - this build uses their pins and timings verbatim (DE-only panel, reset on GPIO46, 23 MHz pclk). Full 16 MB class: OTA updates and the complete airline logo set included. Heads-up: flashing replaces the stock Bambu-remote firmware; a full-flash backup or BTT's published images bring it back. Bonus of the built-in battery: the radar runs untethered for 20-30 minutes.

Panda Touch, 16 MB (0.4.4-pandatouch) - first install: check Erase device

Prefer the command line? Grab the single merged image and flash it in one go: esptool.py --chip esp32s3 --port PORT write_flash 0x0 esp32flight-0.4.4-pandatouch-full.bin (back up first: read_flash 0 0x1000000 stock-backup.bin restores the Bambu remote).

When reporting, include:

  • Does the display come up, with correct colors (red is red, not blue)?
  • Does touch track your finger (not mirrored or offset)?
  • Does the backlight dim correctly (night mode toggle in settings)?

7″ Amazon HMI boards: they are CrowPanel 7.0 rebrands

2026-08-11 · board: Elecrow CrowPanel 7.0 (DIS08070H) and unbranded 7″ rebrands (IoTeikXgo etc., EK9716BD3 driver, 4 MB flash) · base: 0.4.4

Plot twist confirmed by the listing's own support links: the no-name 7″ Amazon boards are rebranded Elecrow CrowPanel 7.0 units - not Suntons. Their PCLK sits on GPIO0 (like the CrowPanel 5.0 we already run) and the data bus differs from the Sunton 7″ too. This build carries Elecrow's official pin map and timings on the 4 MB class (updates via this flasher, no OTA; airline logos load on demand):

CrowPanel 7.0 / 7″ Amazon rebrands, 4 MB (0.4.4-crowpanel70) - first install: check Erase device
Genuine Sunton 8048S070, 16 MB (0.4.4-sunton70) - untested, testers welcome

Elecrow CrowPanel 5.0: display window SOLVED

resolved 2026-08-08 · board: CrowPanel 5.0 (DIS07050H, 4 MB flash)

Hardware-confirmed by the first tester: the blanked left zone was the panel's display window - the Guition-family porch timings this board inherited shifted it off-glass. The classic wide 5″ TFT window (Test C3) puts it where the panel expects it, and that fix is now in the build below. Still experimental (4 MB class: updates via this flasher only, no OTA, logos fetched on demand) - reports welcome before it graduates to the main page.

7B display jitter: SOLVED

resolved 2026-08-08 · the fix ships in the updated 0.4.4-7b build on the main page

Root cause found on affected hardware: PSRAM memory bandwidth. The 1024x600 panel streams ~62 MB/s from PSRAM continuously, and at the 80 MHz our build inherited from the 800x480 boards there was no headroom left for screen updates - units with less silicon margin shook on any activity. Waveshare's own firmware runs PSRAM at 120 MHz; matching it eliminated the shake outright. The same update also makes the map screensaver work on the 7B for the first time. Just reflash from the main page (settings survive) - the old A/B test builds are retired.
